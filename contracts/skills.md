# 技能接口契约 v0.1（草案）

> 杨铮 · 任务编排层
> 状态：草案，待与曹志伟、蒋丰泽、宋红对齐

这份文档规定：编排层调用技能时，**传什么、收什么**。
所有技能实现方按此约定，编排层不关心你内部怎么实现。

---

## 1. 调用方式

每个技能是一个可执行文件，位于 `skills/<技能名>/main`。

```bash
echo '{"target":"球","attempt":1}' | skills/move_to/main move_to
```

- 参数：JSON，走 stdin
- 技能名：argv[1]
- 返回：JSON，走 stdout

> 这是 demo 阶段的形态。接真服务后换成 HTTP（对齐曹志伟的
> `POST /v1/execute`），**但下面的字段约定不变**。

---

## 2. 返回值（所有技能统一）

```json
{
  "success": true,
  "detail": "已移动到 球 附近",
  "evidence": {}
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `success` | bool | 技能自认为成没成。**不是最终判定** |
| `detail` | string | 人话，出错时要说清为什么 |
| `evidence` | object | 判定证据。mock 阶段恒为 `{}`，接视觉后放检测框/位姿/图像路径 |

> 与宋红的 Judge 契约一致，便于后续两条栈合并。

`success: true` 不代表任务真的完成 —— 电机跑到位不等于球被抓起来了。
最终判定由编排层的 Judge 层做。

---

## 3. 编排层额外注入的参数

| 参数 | 类型 | 说明 |
|---|---|---|
| `attempt` | int | 第几次尝试，从 1 开始。技能可据此调整策略（如换抓取姿态） |
